# サーバーレス接続の試作

ホスト1人と参加者1人が同じネットワークで利用する。WebRTC DataChannelを用い、ICEサーバーは指定しない。接続開始時に完全なofferとanswerを手動コピーで交換する。自動発見、シグナリングサーバー、STUN、TURNは使わない。コードには接続情報が含まれるので、相手にだけ渡す。

ホストが正本を保持し、接続後にワールドを分割送信する。参加者の編集はホストに送り、ホストが適用して確定結果を返す。ホスト側での編集も同じ確定通知を送る。送信は順序付き。位置は約150ms間隔で交換する。共同編集中の変更はホストのブラウザに自動保存し、参加者のローカルデータは上書きしない。ホスト切断時は参加者を元のローカルワールドへ戻す。

この試作はホストと参加者の最大2人。回線断中の編集の再送・再接続、参加者の追加、本人認証、QRコード、専用バックアップは未対応。WebRTCのローカル候補の取り扱いやWi-Fiの端末間隔離により、同一ネットワークでもつながらないことがある。実機検証が必要。現在のSitesが非公開の場合、各参加者に閲覧権限が必要。

## ストック

ワールドごとに8種類の共有ストックを持ち、初期値は各16個、上限は各9,999個。ホストがワールドへの編集とストックの増減を一つの処理として判定し、成功時のみ変更と確定後のストックを配信する。参加者の接続前状態にはワールドとストックの両方を保持し、退出時に戻す。ワールドとストックを同一の保存データとして保存し、旧ワールドのみの保存は初期ストックで読み込む。接続コードのバージョン4は旧クライアントとの接続を拒否する。

## クラフト

ホストがレシピIDを検証し、材料と完成品のストックをまとめて更新する。参加者からの要求はホストが確定してから双方に反映し、材料不足や容量上限では変更しない。ホストは変更後のストックを保存する。

## 装備と鉱物

石の初回採掘時に座標から鉄・ダイヤモンドの有無を決定する。採掘済み座標、装備の所持状態、装着スロットをホストのワールドと一緒に保存する。素材、装備の作成と切り替えはホストが確定し両端末で共有する。ゲストが抜けると参加前の状態に戻る。古い8種のストックには鉱物0個と空の装備を補う。
